# OSPF Network Simulator

An interactive, full-stack network simulation platform designed to visualize and analyze Open Shortest Path First (OSPF) routing protocols in multi-area topologies. The application features a dynamic Cytoscape-based frontend and a robust FastAPI backend driven by NetworkX.

---

## 🚀 Features

### 1. Interactive Topology Builder
* **Drag-and-Drop Editor**: Add, position, and label network devices.
* **Device Roles Supported**: 
  * 🌐 **Routers**: OSPF-enabled core forwarding units.
  * 🖥️ **Hosts**: End systems to initiate and receive network traffic.
  * 🔌 **Switches**: Layer 2 local broadcast domain connectors.
* **Custom Interfaces & Links**: Configure IP addresses, subnet masks, link types (OSPF, Ethernet), OSPF cost, and link areas directly.

### 2. Complete OSPF Multi-Area Engine
* **Area Configurations**:
  * **Backbone Area (Area 0)**: The core of the OSPF autonomous system.
  * **Standard Area**: Multi-access or point-to-point non-backbone areas.
  * **Stub Area**: Filters external routes (Type 5 LSAs) and installs a default route to the ABR.
  * **Totally Stubby Area**: Filters both external and inter-area routes, keeping the LSDB compact.
  * **Not-So-Stubby Area (NSSA)**: Imports external routes via Type 7 LSAs while remaining a stub area.
* **Dynamic Router Identification**:
  * **Internal Router**: Interfaces belong to a single OSPF area.
  * **Backbone Router**: Has at least one interface in Area 0.
  * **Area Border Router (ABR)**: Connects multiple areas, coordinating inter-area summary LSAs.
  * **Autonomous System Boundary Router (ASBR)**: Redistributes routes from external networks.

### 3. Step-by-Step OSPF Lifecycle Simulation
* **Neighbor Discovery**: Hello protocol execution to identify neighbors.
* **Database Synchronization**: Database Description (DBD) exchanges.
* **Link State Advertisements (LSAs)**:
  * **Type 1 (Router LSA)**: Advertised by all routers within an area.
  * **Type 2 (Network LSA)**: Generated by the DR (Designated Router) on multi-access links.
  * **Type 3 (Summary LSA)**: Flooded by ABRs to describe inter-area destinations.
  * **Type 4 (ASBR Summary LSA)**: Informs areas how to reach the ASBR.
  * **Type 5 (AS External LSA)**: Generated by ASBRs to advertise external routes (filtered in stubs).
  * **Type 7 (NSSA LSA)**: Advertises external routes inside NSSAs.
* **Area-Specific Flooding**: Restricts LSAs to their proper flooding scope boundaries.

### 4. Routing Table & SPF Computations
* **Dijkstra's SPF Algorithm**: Runs Shortest Path First calculations per area using NetworkX.
* **Routing Table Construction**: Installs routes with preference hierarchy (Intra-area > Inter-area > External).
* **Detailed Breakdown**: View destination subnet, next-hop, path cost, path list, and route type for each device.

### 5. Interactive Ping Simulator & Tracer
* **Visual Traceroute**: Trace ping packets hop-by-hop between any two hosts.
* **OSPF-Aware Routing Paths**: The packet path reflects the actual computed OSPF routing table entries, showing cost validation, destination type, and next-hop decisions.

## 🛠️ Installation & Setup

### Prerequisites
* Python 3.10+
* Web browser (Chrome, Firefox, Edge, Safari)

### 1. Run the Backend API
Navigate to the `api/` directory:
```bash
cd api
```

Create and activate a virtual environment:
```bash
# Windows
python -m venv .venv
.venv\Scripts\activate

# macOS / Linux
python3 -m venv .venv
source .venv/bin/activate
```

Install the required dependencies:
```bash
pip install -r requirements.txt
```

Start the FastAPI application:
```bash
python main.py
```
*The API will start running on **`http://localhost:8001`**.*

### 2. Run the Frontend Client
Since the frontend is a standalone static single-page application, you can:
* **Option A**: Double-click `frontend/index.html` to open it directly in your browser.
* **Option B**: Run a local HTTP server for a smoother experience:
  ```bash
  # From the repository root
  python -m http.server 8000 --directory frontend
  ```
  Then visit **`http://localhost:8000`** in your browser.

## 📖 Usage Examples

1. **Build a Multi-Area Topology**:
   * Click **Add Router** to place three routers (`R0`, `R1`, `R2`).
   * Select `R0` and enable OSPF in **Area 0**.
   * Select `R1` (ABR) and connect it to `R0` (Area 0) and `R2` (Area 1).
   * Click **Simulate OSPF** to see the ABR dynamically register inter-area summary routes.
2. **Observe Flooding Scope**:
   * Set `Area 1` to be a **Stub Area**.
   * Connect an external subnet to `R0` and flag it as an ASBR.
   * View the LSDB of `R2` (in the stub area) to verify that Type 5 (External) LSAs are absent and a default route (`0.0.0.0/0`) has been added.
3. **Execute a Ping Trace**:
   * Add a host to `R0` and a host to `R2`.
   * Open the **Ping Tools** tab.
   * Select source and destination hosts, then click **Run Ping**.
   * Watch the visual trace run step-by-step across OSPF-determined next hops.

## ⚙️ Configuration

* **Backend API URL**: The frontend connects to `http://127.0.0.1:8001` by default. If your backend is hosted elsewhere, edit the `this.backendUrl` variable inside `frontend/index.html`:
  ```javascript
  this.backendUrl = 'http://your-custom-backend-ip:8001';
  ```
* **Vercel Deployments**: The repository contains `vercel.json` and a `Procfile` configured for deployment on serverless platforms using ASGI handlers (e.g., Mangum).
